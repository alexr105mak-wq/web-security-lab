# Лабораторная работа 2. Уязвимое веб-приложение

Веб-приложение на Python и Flask демонстрирует две уязвимости: SQL-инъекцию
в поиске заметок и IDOR при просмотре заметки по номеру. Отдельный Python-скрипт
воспроизводит обе атаки по HTTP, а diff-патч исправляет их.

**Учебный стенд:** уязвимости добавлены намеренно. Все аккаунты и данные
вымышленные. Приложение предназначено для локальной демонстрации и изучения
ошибок безопасности; примеры относятся к этому стенду и системам, которые
пользователь вправе тестировать.

## Части работы

| Часть задания | Артефакты |
|---|---|
| Веб-приложение с двумя уязвимостями | `app.py`, `db.py`, `schema.sql`, `templates/` |
| Эксплуатация из Python | `exploit.py` |
| Исправление уязвимостей | `patches/fix.diff` |
| Результаты до и после исправления | `examples/` |

## Запуск

Требуются Python 3.10 или новее и Git. Проверено на Python 3.14.
SQLite входит в стандартную библиотеку Python; отдельный сервер базы не нужен.

```bash
git clone https://github.com/alexr105mak-wq/web-security-lab.git
cd web-security-lab
```

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m flask --app app run --host 127.0.0.1 --port 5000
```

Linux и macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m flask --app app run --host 127.0.0.1 --port 5000
```

Откройте [страницу входа](http://127.0.0.1:5000/login).
При первом запуске создаётся `instance/notes.sqlite3` с учебными данными.
Повторный запуск не перезаписывает существующие заметки.

| Логин | Пароль | Свои заметки |
|---|---|---|
| `alice` | `alice123` | 1, 2 |
| `bob` | `bob123` | 3, 4 |

В VS Code можно использовать конфигурацию **«Flask: лабораторная № 2»**
и F5. Ключ сессии генерируется при запуске, поэтому после перезапуска
нужно войти заново.

## Как работает

1. Пользователь входит через POST-форму. Пароль проверяется по хешу,
   номер пользователя сохраняется в сессии.
2. Страница `/notes` показывает свои заметки и форму поиска.
3. Страница `/notes/<номер>` отображает отдельную заметку.
4. `exploit.py` получает cookie и токен формы, входит под учебным аккаунтом,
   проверяет обычный доступ и выполняет две демонстрации уязвимостей.
5. `patches/fix.diff` заменяет построение SQL на параметризованный запрос
   и добавляет проверку владельца заметки.

## Уязвимости

| Уязвимость | Причина | Наблюдаемый результат | OWASP Top 10:2021 |
|---|---|---|---|
| SQL-инъекция | Поисковый ввод вставляется в SQL через f-строку | В результатах появляются названия и номера чужих заметок | [A03 — Injection](https://top10.owasp.org/2021/A03_2021-Injection/) |
| IDOR | После входа не проверяется владелец заметки | Изменение номера в URL позволяет прочитать чужую заметку | [A01 — Broken Access Control](https://top10.owasp.org/2021/A01_2021-Broken_Access_Control/) |

Исходная версия в `main` намеренно уязвима. Для сравнения с исправленной
версией используется патч, а не изменение скрипта демонстрации.

## Эксплуатация из Python

Оставьте Flask работающим. Следующие команды выполняйте в **другом терминале**
из папки проекта. Скрипт использует только стандартные модули Python.

```powershell
.\.venv\Scripts\python.exe .\exploit.py --expect vulnerable
.\.venv\Scripts\python.exe .\exploit.py --account bob --expect vulnerable
```

Для Linux/macOS используйте `.venv/bin/python exploit.py` с теми же параметрами.
По умолчанию скрипт обращается к `http://127.0.0.1:5000` под `alice`.
Другой адрес своего экземпляра можно передать через `--base-url`.

Ожидаемый итог:

```text
[RESULT] SQLi=VULNERABLE; IDOR=VULNERABLE
[EXPECT] vulnerable: PASS
```

Для `alice` обычный список — `[1, 2]`, а результат SQL-инъекции — `[1, 2, 3, 4]`.
IDOR позволяет прочитать `/notes/4` с учебной строкой `BOB-DEMO-73`.
Для `bob` аналогично раскрываются заметки Алисы.

## Применение исправлений

Остановите Flask: Ctrl+C в терминале или Shift+F5 при запуске через отладчик.
Из корня проекта выполните:

```bash
git -c core.autocrlf=false apply --check patches/fix.diff
git -c core.autocrlf=false apply patches/fix.diff
```

Патч изменяет `app.py` и два файла тестов. В поиске используются параметры `?`,
а просмотр чужой заметки возвращает HTTP 403. Флаг `core.autocrlf=false`
сохраняет переводы строк и действует только на эту команду.

Запустите Flask заново той же командой и повторите демонстрацию:

```powershell
.\.venv\Scripts\python.exe .\exploit.py --expect fixed
.\.venv\Scripts\python.exe .\exploit.py --account bob --expect fixed
```

Ожидаемый итог:

```text
[RESULT] SQLi=BLOCKED; IDOR=BLOCKED
[EXPECT] fixed: PASS
```

Для возврата к исходной версии остановите сервер и отмените патч:

```bash
git -c core.autocrlf=false apply --reverse --check patches/fix.diff
git -c core.autocrlf=false apply --reverse patches/fix.diff
```

## Проверки и результаты

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

В исходной версии тесты подтверждают воспроизведение учебных уязвимостей.
После патча они проверяют блокировку тех же атак. В обеих версиях проверяются
также вход, обычный поиск, свои заметки, выход и сохранность данных.
Тесты используют временную базу.

Выполнены 15 тестов до патча и 15 после. Неизменённый `exploit.py` проверен
для обоих аккаунтов в двух состояниях. Применение и отмена патча проверены.

- [Вывод до исправления](examples/exploit-vulnerable.txt).
- [Вывод после исправления](examples/exploit-fixed.txt).
- [Итог проверки патча](examples/patch-verification.txt).

Коды завершения `exploit.py`: `0` — результат совпал с ожиданием,
`1` — не совпал, `2` — ошибка выполнения.
