# Подробные пояснения к лабораторной работе 2

Пояснения к коду и этапам создания учебного стенда. Команды выполняются из корня проекта. Краткая инструкция и состав работы приведены в [README](../README.md).

## Запуск из VS Code

Откройте в VS Code папку `lab2_flask` целиком.

- `F5` — запуск с отладкой. Конфигурация называется «Flask: лабораторная № 2».
- `Ctrl+F5` — запуск без отладки.
- После запуска откройте http://127.0.0.1:5000/ в браузере.
- `Shift+F5` — остановка сеанса отладки.

Путь к Python из `.venv` указан явно в `.vscode/launch.json`.
Встроенный отладчик Flask и автоперезагрузка отключены; при работе с F5
отладку выполняет VS Code.

Также файл `app.py` поддерживает кнопку Python «Run Python File»
в правом верхнем углу редактора. Для неё должен быть выбран интерпретатор
`.venv\Scripts\python.exe` (команда `Python: Select Interpreter`).

Запускайте один экземпляр сервера за раз. Если порт 5000 занят,
сначала остановите предыдущий запуск. После изменения кода перезапустите
приложение.

## Запуск в Windows PowerShell

Перейдите в папку проекта:

```powershell
cd 'C:\path\to\web-security-lab'
```

Окружение `.venv` и зависимости на этом компьютере уже подготовлены.
Запустите сервер:

```powershell
.\.venv\Scripts\python.exe -m flask --app app run --host 127.0.0.1 --port 5000
```

Откройте http://127.0.0.1:5000/ в браузере. Остановка сервера: `Ctrl+C`
в том же терминале. Активация окружения для этой команды не требуется.

Из папки проекта выполните команды, используя обычную установку Python

## Шаг 2: параметры запроса

- `/` — главная страница с формой и примером ссылки на приветствие.
- `/hello?name=Саша` — выводит «Привет, Саша!».
- `/hello?name=Александр` — выводит «Привет, Александр!».
- `/hello` — выводит «Привет, гость!», поскольку параметр отсутствует.

В адресе `/hello?name=Саша` путь — `/hello`, а `name=Саша` — параметр
после знака `?`. Flask разбирает параметры в `request.args`.
Вызов `request.args.get("name", "гость")` получает значение `name`
или строку «гость», если параметра нет.

`escape(name)` преобразует специальные HTML-символы пользовательского
ввода, чтобы имя отображалось как текст. Например, `<b>Саша</b>`
показывается вместе с угловыми скобками, а не становится жирным текстом.

После изменения `app.py` перезапустите сервер: остановите его через
`Ctrl+C` и снова выполните команду запуска. Автоперезагрузка выключена.

Учебные уязвимости описаны в шагах 5 и 6, скрипт эксплуатации — в шаге 7.
Исправления и команды применения патча описаны в шаге 8.

## Шаг 3: HTML-форма и шаблон

Функция `index()` возвращает `render_template("index.html")`.
Flask ищет этот файл в папке `templates` рядом с `app.py` и формирует HTML-ответ.

В `templates/index.html` расположена форма:

```html
<form action="/hello" method="get">
    <label for="name">Твоё имя:</label>
    <input type="text" id="name" name="name" required>
    <button type="submit">Поздороваться</button>
</form>
```

- `action="/hello"` задаёт путь, куда отправляются данные.
- `method="get"` помещает данные формы в параметры адреса.
- `name="name"` задаёт название параметра. Его читает `request.args.get("name", "гость")`.
- `id="name"` связывает поле с подписью `label for="name"`.
- `type="submit"` делает кнопку отправкой формы.
- `required` требует заполнить поле при обычной отправке формы браузером.

Введите имя и нажмите «Поздороваться»: браузер откроет `/hello?name=...`.
Значение кодируется для передачи в URL; Flask декодирует его обратно в строку.
Обработчик `/hello` возвращает приветствие и ссылку назад к форме.

## Шаг 4: пользователи и заметки

После запуска откройте http://127.0.0.1:5000/login.

| Логин | Пароль | Номера своих заметок |
| --- | --- | --- |
| `alice` | `alice123` | 1, 2 |
| `bob` | `bob123` | 3, 4 |

Все аккаунты, пароли и заметки учебные. Регистрация и редактирование заметок
на этом шаге не предусмотрены.

SQLite доступна через стандартный модуль Python `sqlite3`, отдельный сервер
базы данных устанавливать не нужно. При первом запуске автоматически создаётся
`instance/notes.sqlite3` с таблицами `users` и `notes`. У заметки есть `id`,
`owner_id` (номер владельца), `title` и `content`.
Повторный запуск добавляет только отсутствующие учебные записи и не перезаписывает
существующие заметки. Папка `instance` исключена из Git: база воспроизводится
по `schema.sql` и данным в `db.py`.

Форма входа отправляет логин и пароль методом POST. Обработчик читает их через
`request.form`, проверяет пароль по хешу и сохраняет номер пользователя в сессии.
В базе лежат хеши паролей, а не исходные пароли. Ключ подписи сессии генерируется
при запуске сервера, поэтому после перезапуска нужно войти заново.
POST-формы входа и выхода также передают скрытый `csrf_token`, который проверяет сервер.

Маршруты:

- `GET /login` — форма входа; `POST /login` — проверка логина и пароля.
- `POST /logout` — выход из аккаунта.
- `GET /notes` — список своих заметок.
- `GET /notes?q=план` — поиск по названию и тексту своих заметок.
- `GET /notes/1` — отдельная заметка; после входа доступны и чужие (IDOR), отсутствующая возвращает HTTP 404.

Для страниц заметок требуется вход. Запросы входа и просмотра отдельной заметки
используют параметры `?`. Просмотр отдельной заметки намеренно не проверяет владельца.
Поиск намеренно использует уязвимое построение SQL из строки пользователя
(см. шаг 5). IDOR описана в шаге 6.

## Шаг 5: первая уязвимость — SQL-инъекция

Категория: [OWASP Top 10:2021 A03 — Injection](https://top10.owasp.org/2021/A03_2021-Injection/), CWE-89.

Уязвимость находится в обработчике `notes()` в `app.py`.
Значение параметра `q` вставляется непосредственно в SQL через f-строку:

```python
sql = (
    f"SELECT id, title FROM notes WHERE owner_id = {g.user['id']} "
    f"AND (title LIKE '%{query}%' OR content LIKE '%{query}%') ORDER BY id"
)
```

В обычном запросе `q=план` база ищет названия и текст, содержащие «план»,
среди заметок текущего пользователя. Пользовательский ввод должен быть данными,
но в этом варианте он может изменить структуру SQL-запроса.

Демонстрация на локальном приложении:

1. Запустите приложение и войдите как `alice` / `alice123`.
2. Откройте «Мои заметки»: доступны названия только двух заметок Алисы.
3. Введите в поле поиска следующую строку (пробел после `--` можно сохранить):

```text
') OR 1=1 --
```

4. Нажмите «Найти». В результатах появятся названия всех четырёх заметок,
   включая «План Боба» и «Личная заметка Боба».

Для пользователя alice итоговый запрос будет выглядеть так:

```sql
SELECT id, title FROM notes WHERE owner_id = 1 AND (title LIKE '%') OR 1=1 -- %' OR content LIKE '%') OR 1=1 -- %') ORDER BY id
```

`'` закрывает строковый литерал, `)` закрывает скобку условия поиска,
`OR 1=1` делает условие истинным для каждой записи, а `--` комментирует
оставшуюся часть запроса. Ограничение по владельцу больше не исключает чужие записи.

Это раскрытие названий и номеров чужих заметок через поиск.
Для этой демонстрации достаточно результатов поиска: SQL-инъекция раскрывает
названия и номера чужих заметок. Чтение чужой заметки через `/notes/4`
является отдельной уязвимостью IDOR и описано в шаге 6.

Некорректный SQL, например поиск строки `';`, возвращает HTTP 400
с сообщением об ошибке запроса.

## Шаг 6: вторая уязвимость — IDOR

Категория: [OWASP Top 10:2021 A01 — Broken Access Control](https://top10.owasp.org/2021/A01_2021-Broken_Access_Control/), CWE-639.
IDOR (Insecure Direct Object Reference) — доступ к чужому объекту по его
идентификатору без необходимой проверки прав на этот объект.

В `note_detail()` проверяется, что пользователь вошёл, затем заметка загружается
по номеру `note_id`. Сравнения `note['owner_id']` с `g.user['id']` нет:

```python
note = get_db().execute(
    "SELECT * FROM notes WHERE id = ?", (note_id,)
).fetchone()
if note is None:
    abort(404)

return render_template("note.html", note=note)
```

Демонстрация без SQL-инъекции:

1. Перезапустите приложение и войдите как `alice` / `alice123`.
2. Обычный список `/notes` показывает только две заметки Алисы.
3. Откройте свою заметку `/notes/2`.
4. Измените номер в адресе на `/notes/4`.
5. Вместо прежнего HTTP 403 сервер вернёт HTTP 200 и текст «Личной заметки Боба»,
   содержащий учебную строку `BOB-DEMO-73`.

Пользователь всё ещё alice; пароль Боба и SQL-инъекция не нужны.
Аналогично bob может открыть `/notes/2` и увидеть учебную строку `ALICE-DEMO-42`.
Без входа страницы заметок перенаправляют на `/login`, а несуществующий номер
по-прежнему возвращает HTTP 404.

SQL-параметр `?` защищает этот запрос от SQL-инъекции, но не проверяет права
на запись: проверка номера и проверка владельца решают разные задачи.
Для исправления IDOR потребуется сравнить владельца с текущим пользователем
и отказать в доступе к чужой записи на сервере.

## Шаг 7: эксплуатация из отдельного Python-скрипта

`exploit.py` использует только стандартные модули Python. Скрипт не импортирует
приложение и не читает базу: все действия выполняются HTTP-запросами.

Порядок работы:

1. GET `/login`: получить страницу, CSRF-токен и cookie сессии.
2. POST `/login`: передать учебные логин, пароль и токен формы.
3. GET `/notes` и GET своей заметки: подтвердить успешный вход и обычный доступ.
4. GET `/notes?q=...` с SQL-фрагментом: сравнить номера результатов с обычным списком.
5. GET чужой заметки по известному номеру: проверить статус и наличие её учебного текста.
6. Вывести отдельный результат SQL-инъекции и IDOR.

### Запуск в VS Code

Сначала запустите Flask (конфигурация «Flask: лабораторная № 2») и оставьте его
работать. Откройте `exploit.py` и нажмите кнопку Python «Run Python File» вверху
редактора. Для скрипта также добавлена конфигурация «Демонстрация: exploit.py».
Вывод появится во встроенном терминале VS Code.

Либо откройте **новый** терминал VS Code в папке проекта и выполните:

```powershell
.\.venv\Scripts\python.exe .\exploit.py
```

По умолчанию используется `alice` и адрес `http://127.0.0.1:5000`.
Для второго учебного пользователя:

```powershell
.\.venv\Scripts\python.exe .\exploit.py --account bob
```

Для другого адреса своего экземпляра приложения:

```powershell
.\.venv\Scripts\python.exe .\exploit.py --base-url http://127.0.0.1:5001
```

В уязвимой версии ожидается итог:

```text
[RESULT] SQLi=VULNERABLE; IDOR=VULNERABLE
[EXPECT] vulnerable: PASS
```

Для alice обычный список содержит `[1, 2]`, после SQL-инъекции — `[1, 2, 3, 4]`,
а запрос `/notes/4` раскрывает текст с `BOB-DEMO-73`.
Для bob обычный список — `[3, 4]`, атака раскрывает `[1, 2, 3, 4]`,
а `/notes/2` содержит `ALICE-DEMO-42`.

Опция `--expect fixed` используется для повторной демонстрации после применения
патча. Она ожидает отсутствие чужих записей в поиске и HTTP 403 для чужой заметки.
На текущей уязвимой версии этот режим должен завершиться с `FAIL`.

Коды завершения: `0` — результат совпал с ожиданием, `1` — не совпал,
`2` — ошибка подключения, входа или несовпадение с учебными данными.
Ошибка выполнения не считается успешной блокировкой атаки.

## Шаг 8: исправление обеих уязвимостей через diff

Патч: `patches/fix.diff`. Он изменяет `app.py`. Сам `exploit.py` не меняется: один и тот же клиент
показывает результат до и после исправления.

### Что исправляется

1. **SQL-инъекция.** Текст SQL больше не формируется из пользовательского ввода.
   `owner_id` и поисковые шаблоны передаются отдельными параметрами `?`.
   Кавычки, скобки, `OR` и `--` в строке поиска рассматриваются как данные.
2. **IDOR.** Перед показом заметки сервер сравнивает `note['owner_id']`
   с `g.user['id']`. При несовпадении возвращается HTTP 403 без текста заметки.

Подходы соответствуют рекомендациям OWASP:
[параметризованные SQL-запросы](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html)
и [проверка прав на объект](https://cheatsheetseries.owasp.org/cheatsheets/Insecure_Direct_Object_Reference_Prevention_Cheat_Sheet.html).

### Демонстрация до исправления

Запустите Flask, затем в отдельном терминале из папки `lab2_flask` выполните:

```powershell
.\.venv\Scripts\python.exe .\exploit.py --expect vulnerable
```

Ожидается `SQLi=VULNERABLE; IDOR=VULNERABLE` и `vulnerable: PASS`.

### Применение патча

Остановите запущенный Flask. При отладочном запуске в VS Code — `Shift+F5`.
В терминале **из папки `lab2_flask`** выполните:

```powershell
git -c core.autocrlf=false apply --check .\patches\fix.diff
git -c core.autocrlf=false apply .\patches\fix.diff
```

Первый вызов проверяет применимость патча, второй меняет файлы.
Git должен быть установлен; для `git apply` инициализация репозитория не требуется.
Параметр `-c core.autocrlf=false` сохраняет переводы строк при применении
и отмене патча в Windows. Он действует только для этой команды.

Запустите Flask заново через F5. В другом терминале выполните:

```powershell
.\.venv\Scripts\python.exe .\exploit.py --expect fixed
.\.venv\Scripts\python.exe .\exploit.py --account bob --expect fixed
```

Ожидаемый итог для обоих аккаунтов:

```text
[RESULT] SQLi=BLOCKED; IDOR=BLOCKED
[EXPECT] fixed: PASS
```

Обычный поиск и просмотр своих заметок продолжают работать. SQL-фрагмент
не раскрывает чужие записи, а чужая заметка возвращает HTTP 403.

### Возврат к уязвимой версии

Остановите Flask и из той же папки выполните:

```powershell
git -c core.autocrlf=false apply --reverse --check .\patches\fix.diff
git -c core.autocrlf=false apply --reverse .\patches\fix.diff
```

После перезапуска снова используйте `--expect vulnerable`.
